# SnapKiosk Technical Design

## Architecture

Use a feature-oriented React Native CLI application. UI components call feature hooks/use cases; use cases depend on service interfaces; platform-specific implementations are selected behind those interfaces. Redux Toolkit holds transient workflow state and observable queue/status state. SQLite is the durable source for settings, templates, sessions, print attempts, and upload jobs. Images live in app-private files and are referenced by path rather than stored as large database blobs.

```text
src/
  app/                 navigation, providers, startup and theme
  components/          buttons, cards, dialogs, status and form controls
  features/
    welcome/ booth/ admin/ templates/ sessions/ printing/ delivery/
  services/
    camera/ composition/ database/ printer/ storage/ payments/ kiosk/
  store/               Redux Toolkit store and slices
  hooks/               permissions, idle timer, connectivity
  theme/               tokens, typography, responsive helpers
  utils/               validation, IDs, dates, image math
```

Keep native integration behind interfaces:

- `CameraAdapter`: permission, devices, photo capture, capture metadata.
- `CompositionAdapter`: high-resolution digital composition, thermal composition, preview/export.
- `PrinterAdapter`: discover/paired devices, connect, status, raster print, feed/cut/disconnect.
- `DeliveryAdapter`: request upload target, upload asset, resolve private download, expire/delete.
- `KioskAdapter`: immersive mode, wake lock, lock-task capability/status.
- `PaymentAdapter`: create/verify payment; manual confirmation is a separate trusted operator action.

## Core data model

SQLite tables (migration versioned):

- `settings(key PRIMARY KEY, value_json, updated_at)` — device and workflow settings; secrets stored using native secure storage and referenced by key.
- `event_profiles(id, name, config_json, enabled, created_at, updated_at)` — branding and event overrides.
- `templates(id, name, version, layout_json, enabled, created_at, updated_at)` — normalized canvas and ordered elements.
- `sessions(id, created_at, completed_at, event_profile_id, template_id, status, consent_at, session_json, digital_path, thermal_path, upload_status, download_expires_at, payment_status)`.
- `session_photos(id, session_id, ordinal, local_path, captured_at, filter_id, metadata_json)`.
- `print_jobs(id, session_id, printer_id, copies, status, attempt_count, last_error, created_at, updated_at)`.
- `print_attempts(id, job_id, started_at, finished_at, status, error_code, error_message)`.
- `upload_jobs(id, session_id, asset_path, status, attempt_count, retry_at, remote_key, expires_at, last_error)`.
- `audit_events(id, kind, created_at, detail_json)` — administrator changes and operational events, excluding photo content/secrets.

Use UUIDs for local record identifiers and cryptographically random tokens generated by the backend for customer delivery. Database migrations must support rollback/recovery and schema versioning.

## Template representation

Templates use a fixed logical canvas (`width`, `height`, `unit: "normalized"`) independent of screen DPI. Each element has an ID, type, normalized `x/y/width/height`, rotation, z-index, and typed properties. Photo slots reference capture indexes. QR elements render from a private delivery URL at export time. Validate bounds, required photo references, supported fonts, and export dimensions before enabling a template.

## Session state machine

`welcome → consent → layout → theme/filter → capture → review → compose → print → delivery → thank-you → welcome`

Optional steps are skipped by configuration. A session persists after each capture and status transition. Recover interrupted sessions to an operator recovery screen, never to another customer's customer-facing preview. Print and upload queues are independent so a cloud outage cannot block local printing.

## Printing pipeline

1. Export final layout at target dot width and sufficient height.
2. Render photographic regions in grayscale and apply configured tone correction and dithering.
3. Render QR, small text, and logos as separate sharp monochrome overlays with quiet zone preserved.
4. Pack rows into ESC/POS raster bytes, split into bounded chunks, and enqueue one durable job per requested copy.
5. Send through the platform adapter; track acknowledgements where protocol supports them. Retry only with operator/customer clarity to avoid silent duplicate prints.

Initial defaults are 384 dots for nominal 58 mm and 576 dots for nominal 80 mm, editable per printer. Do not infer physical printable width from paper roll label alone.

## Security and privacy

- PIN hash/verification uses a maintained password hashing implementation or platform secure credential facility, with retry delay and lockout. Never store plaintext PIN in SQLite or Redux.
- Local photos are app-private. File names are opaque IDs, not names or event descriptions.
- The mobile application receives short-lived upload/download authorization from a backend; no service account keys are shipped in the bundle.
- Delivery pages resolve only an opaque token, enforce expiry, and set restrictive cache headers. Public object listing remains disabled.
- Consent, retention, deletion, and upload status are visible to the operator. Delete local originals when the configured retention expires.

## Navigation and UI

- `CustomerStack`: Welcome, consent, layout/theme, capture, review, print/delivery, thank-you. Hide system chrome where supported.
- `AdminStack`: authenticated dashboard with tablet sidebar and compact phone navigation. Settings and template editing remain outside the customer stack.
- Shared design tokens support cream/charcoal/pastel light theme and a low-glare dark theme. Controls use large touch targets and explicit disabled/loading/error states.
- Long-press logo for five seconds opens PIN entry; it does not bypass authentication.

## Environment configuration

Commit `.env.example` only. Public app settings may be bundled; secrets and storage service credentials must remain server-side. Build-time variables include environment name, API base URL, and non-secret feature flags. Validate required configuration at startup and display an administrator diagnostic if cloud delivery is not configured.

## Testing strategy

- Unit tests: state transitions, countdown, layout validation/serialization, image transforms, dithering, raster packing, QR sizing, retry/backoff, PIN lockout.
- Integration tests: SQLite persistence/recovery, queue retry, navigation guards, mock printer behavior, upload adapter behavior.
- Device QA: Android tablet camera orientation, permissions, app restart, immersive/kiosk setup, 58/80 mm printers; iOS camera and only supported BLE/vendor printer paths.
- Development mock printer must label every output/status as simulated and never be selectable as a production printer.
